# scs-schema — project context for Claude

Schema database for the SCS IntelliSense VS Code extension
(`duhnunes/scs-intellisense`). It describes the unit classes (`class_name`)
of SCS Software games (ETS2 / ATS) and their attributes, taken from the SCS
modding wiki, and is served to the extension through the jsDelivr CDN.
Owner: DuH Nunes (GitHub: `duhnunes`). Default branch: `master`.

## How to work with the owner
- Writes in Brazilian Portuguese: reply in Portuguese. Code, comments and
  commit messages are in English.
- Web/frontend background, not an experienced programmer: explain the *why*.
- Never present a guess as a fact. Say "not confirmed" instead of inventing.
- Commit messages must be Conventional Commits: `scripts/update.mjs` reads
  them to decide version bumps (see "Pipeline"). Give a message after each
  batch of changes.

## Sources and the one rule for schema content
Format v3 (since 2026-10). Three sources, each for its own part:
- **Generated from the game** (ATS 1.61 engine class tables, extracted in the
  private `B:\Programing\scs-research` folder by
  `scripts/extract-classes.mjs` + `generate-schemas.mjs`): the class list,
  each class's attributes, `type`, `isArray`, enum `values`, `pointsTo`,
  `status` and `superclass`. Contributors don't edit these; the generator
  refreshes them and keeps every hand-written field.
- **SCS modding wiki**, page of *that exact class*: descriptions, defaults,
  `required`, `versionNote`, localization, `allowsSiiNunitRoot`.
- **SCS game files** (`.sii`/`.sui` in the `.scs` archives): how attributes
  are really used (extensions, token values). When wiki and game files
  disagree, write what the files do and keep the wiki's version in `notes`.
The owner doesn't want the executable named as a source in the public repo:
notes use neutral wording ("Not documented on the wiki.", "SCS files use
.pmd"), never a false source. Nothing decompiled goes into the repo; only
facts (names, types, array-ness, parent, enum names, pointer targets).

Still the rule: silence in the sources becomes silence in the JSON
(`""`/`null`/`false`). "Not documented" isn't "doesn't exist". Never infer
from a sibling class. Mistakes already caught this way: `internalOnly: true`
copied from `trailer` onto an unrelated class; `expectedExtensions` set on an
`owner_ptr`; `allowsSiiNunitRoot: false` without the wiki saying so.

## Layout
- `data/schemas/` — source, **flat**: one file per class (1,308 in ATS 1.61),
  `::` written as `.` (`ui::text_common` → `ui.text_common.json`), `scope`
  equal to the file name with `.` → `::`. No subfolders.
- `data/dist/v3/`, `data/manifest.v3.json` — generated by CI. Never edit.
- `data/dist/*.json`, `data/manifest.json` — frozen v2 output, kept so old
  extension versions keep working. Never edit, never regenerate.
- `data/game-usage.json` — units per class in SCS game files (ATS 1.61, 16 of
  66 archives: base, core, def, effect, share, base_vehicle + 10 DLCs; truck
  DLCs mostly missing, so undercounted). Written by
  `scs-research/scripts/export-game-usage.mjs` from the scs-intellisense class
  inventory; re-run it when more archives are extracted. Feeds `gameUnits`.
- `docs/migrating-to-v3.md` — v2 → v3 guide for data consumers.
- `scripts/` — `update.mjs`, `build.mjs`, `validate.mjs`, `formatter.mjs`,
  `log.mjs`, `lib/inheritance.mjs`, `ci/` (workflow-only: `pr.mjs`,
  `check-pr.mjs`, `merge-prs.mjs`)
- `.vscode/db.schema.json` — JSON Schema (draft-07) of the source format
- `.github/workflows/` — `checker.yml`, `builder.yml`
- `CONTRIBUTING.md` — the field-by-field guide for contributors
- Local commands: `pnpm validate`, `pnpm format:schemas`.

## Source file format v3 (details: `CONTRIBUTING.md`, `db.schema.json`)
Class level: `meta.version`, `meta.documentationStatus`
(`complete`/`wip`/`undocumented`), `scope`, `description`, `superclass`,
`versionNote`, `allowsSiiNunitRoot`, `key`.
Attribute level (all 13 always present): `description, type, isArray, values,
pointsTo, status, default, expectedExtensions, required, versionNote,
supportsLocalization, internalOnly, notes`.

Decisions behind it:
- `type` is ONE engine type name (34: string, token, float, …, uint, int,
  enum, quat, volatile_link_ptr, float4x4, aabox…). The engine declares one
  type per attribute; variations in files (`1` vs `1.0`, quoted tokens) are
  text forms of that type, not other types. Arrays: `type` = element type +
  `isArray: true`; both array syntaxes (`key[]:` and `key: N` + `key[i]:`)
  are valid for every array (wiki "Arrays" section), so v2's
  `arrayElementType`/counted-array split is gone.
- `enum`: `values` = engine names (null when the engine has no readable
  names). `token`: `values` only when a source lists the literals.
- `status: "legacy"` = engine record with no member offset (581 in 1.61):
  accepted but not stored, e.g. `sound_horn` replaced by `sounds`. Meaning is
  inference, not confirmed: don't suggest, don't flag as error.
- `default` is its own field (v2 hid it in `notes`).
- `internalOnly: true` = not meant for mods (engine/save-game managed, or
  SCS-only such as `steam_inventory_id`, decided by the owner).
- `superclass` is the direct parent; `"unit"` = root. Never copy inherited
  attributes into `key`.
- `versionNote` stays one free-text field, display-only.
- `dynamicAttributeGroups` was removed: the engine names every attribute
  (`accessory_interior_data` has 221).
- Per-game data (`games`) was considered and postponed: only ATS was
  extracted (the owner has no ETS2). Adding it later is non-breaking.
- `meta.version` is bumped automatically. Don't edit it.

## Pipeline
- `update.mjs` — bumps `meta.version` in `data/schemas/` from the Conventional
  Commits since the last `ci(update):` or `ci(build):` commit (`BREAKING CHANGE` or `!:` →
  major, `feat` → minor, otherwise patch; a new file gets `0.1.0`). Never
  touches the manifest or `dist/`.
- `build.mjs` — two phases. `--dist-only` writes `data/dist/v3/` (flattening via
  `lib/inheritance.mjs`); `--manifest-only <ref>` writes `manifest.v3.json`
  against that commit. They are split because manifest URLs are pinned to a
  commit SHA and must point at a commit where `dist/` already exists —
  computing the ref before committing `dist/` produced URLs that 404'd on the
  CDN. A manifest entry's URL is only rewritten when its hash changed. With
  no flag it runs both (fine for a local preview; CI uses the split).
- `validate.mjs` — shape via ajv + cross-file checks: `scope` equals the file
  name (`.` → `::`), `superclass` and `pointsTo` classes exist, no inheritance
  cycle, no duplicate `scope`.
- `formatter.mjs` — field order and array normalization. Never invents
  missing fields, so `validate.mjs` still catches omissions.
- Manifest v3: `formatVersion` (`3.1.0`; 3.x only adds optional fields),
  `generatedAt` (kept when nothing else changed, so CI makes no empty
  commit), and per class, sorted by scope: `name, description, url, hash,
  metaVersion, size, superclass, documentationStatus, gameUnits` (requested
  by the extension to rank class completion: documented, then used in game
  files, then the rest).
- Workflows: `checker.yml` (`pull_request_target`, read-only contents)
  checks every PR push: overlays the PR's `data/schemas/*.json` blobs onto a
  master checkout and runs master's `validate.mjs`; rejects edits to
  `data/dist/`/`manifest.json`/`manifest.v3.json` and non-plain schema paths; labels
  `validated` (schema-only + valid), `invalid-schema` (+ comment),
  `documentation`/`system` (left for the owner), `awaiting-approval` (+ one
  comment) when approval is needed. Approval gate (`approvalReasons`,
  `isApproved` in `scripts/ci/pr.mjs`): authors whose `author_association`
  isn't OWNER/MEMBER/COLLABORATOR/CONTRIBUTOR, and PRs deleting a schema,
  merge only with an APPROVED review by an OWNER/MEMBER/COLLABORATOR whose
  `commit_id` is the head SHA (a later CHANGES_REQUESTED/DISMISSED cancels
  it). `builder.yml` (cron 00:00
  UTC + manual) re-checks each `validated` PR against current master,
  squash-merges it via the API pinned to the checked SHA (PR title + `(#N)`,
  `Co-authored-by` trailers), `conflict` on 405; then on master: update →
  formatter → validate → commit `ci(update):` → `build --dist-only` →
  `git add -f` → commit → `build --manifest-only <HEAD>` (always; no commit
  when unchanged) → commit → plain push (never rebase: it would change the
  pinned SHA).
- Security rule: both workflows hold a write token, so they must never run
  code from a PR (no checkout of the PR, no PR scripts, no `${{ }}` of PR
  text inside `run:`). PR files are read as data with `git show`. The old
  `proxy.yml` violated this (script injection via PR title/body, and fork
  scripts executed with `contents: write`) and was removed.
- The build must run in CI, not locally: it needs the real commit SHA.
- The squash commit message is the PR title, so the PR title decides the
  version bump (`feat` → minor, etc.).
